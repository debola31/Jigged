# Divergence report — Dashboard (#340)

Method: compared `docs/modules/dashboard.md` against the live dashboard page (`app/dashboard/[companyId]/page.tsx`), its components (`components/dashboard/PinnedMetrics.tsx`, `MetricScorecard.tsx`, `MetricPickerModal.tsx`, `RecentActivity.tsx`, `QuickActions.tsx`), the access layer (`utils/dashboardAccess.ts`), the `/activity` page, the schema snapshot (`supabase/schema.prod.sql`), and the tests under `__tests__/utils/` and `__tests__/components/dashboard/`.

## Fixed in this PR

- **Fixed summary cards replaced by a configurable pinned-metrics scorecard.** The doc described three hard-coded cards (Open Quotes, Jobs Not Started, Revenue This Week). The real dashboard renders `PinnedMetrics` — a scorecard of up to 4 user-chosen metrics drawn from six available (`open_quotes`, `not_started_jobs`, `in_progress_jobs`, `revenue`, `completed_jobs`, `overdue_jobs`), reorderable via `MetricPickerModal`, with a global Today / This Week period toggle and a pager over the remaining metrics. Defaults are `[overdue_jobs, open_quotes, not_started_jobs, in_progress_jobs]`. Rewrote the "Summary Cards" section to describe the actual scorecard + picker + period toggle, and added a persistence note. *Changed: Summary Cards section, Acceptance Criteria.*

- **`jobs.status` / `jobs.shipped_at` no longer exist (dual-status model).** The doc's queries referenced `status = 'not_started'`, `status = 'shipped'`, and `jobs.shipped_at`. Schema now has `production_status` (`not_started | in_progress | completed | cancelled`) and `fulfillment_status` (`unshipped | partially_shipped | fully_shipped`); there is no `status` or `shipped_at` column on `jobs`. Corrected the Jobs-Not-Started query to `production_status = 'not_started'` and the Revenue query to `fulfillment_status = 'fully_shipped'`. *Changed: Summary Cards queries.*

- **Revenue sums `quote_line_items.total_price`, not `quotes.total_price`, and buckets on `updated_at`.** The doc said "Sum of `quotes.total_price` … where `shipped_at` >= start of week". There is no `quotes.total_price` column; revenue is summed from the related `quote_line_items.total_price` for jobs whose `fulfillment_status = 'fully_shipped'`, bucketed by `updated_at` within the selected period (`getRevenueInRange`). Corrected the query text. *Changed: Card "Revenue" query.*

- **Recent Activity is a UNION-on-read over real tables (incl. `shipments`), capped at 6, not "quotes+jobs by timestamp, LIMIT 10".** The doc said activity is inferred only from `quotes`/`jobs` timestamps, limited to 10, and that "shipped" comes from `jobs.shipped_at`. Reality: `getDashboardActivity` merges `jobs` (created/completed), `quotes` (created), and the `shipments` table, newest-first, default limit 6. The dedicated `/activity` page (`getActivityStream`) additionally surfaces `job_notes` (as note/photo) and `job_operations` completions, with type filters and `before`-cursor pagination. Updated the Recent Activity section and removed the stale "shipped inferred from `shipped_at`" claim. *Changed: Recent Activity section.*

- **"View All" activity is shipped, not a future feature.** The doc marked "View All" as a future Activity-log page. The `/activity` route exists (`app/dashboard/[companyId]/activity/page.tsx`) and `RecentActivity` links to it ("View all activity"). Updated the prose. *Changed: Recent Activity "View All" note.*

- **Removed the stale "+ New Job" acceptance-criteria bullet.** The `/jobs/new` route and button were removed (jobs are created only via quote conversion) — the doc's own Quick Actions note already says so, but the AC list still asserted `"+ New Job" button navigates to job creation`. There is no `/jobs/new` route. Dropped the bullet. *Changed: Acceptance Criteria.*

- **Added the missing pinned-metric persistence AC.** No bullet covered saving/reordering pinned metrics or the period toggle persisting across reload — both write to `user_preferences.preferences` (`dashboard_pinned_metrics`, `dashboard_metric_periods`). Added edit→save→reload bullets. *Changed: Acceptance Criteria.*

## Resolved (owner decision)

- **The dashboard has no "New Quote" (or any) create CTA — the doc and a `QuickActions` component both described one.** `components/dashboard/QuickActions.tsx` renders a "New Quote" button linking to `/dashboard/{companyId}/quotes/new`, but it is imported nowhere except the barrel `components/dashboard/index.ts` — the live `page.tsx` never mounts it. **Decision:** the Quick Actions / New Quote CTA was **intentionally dropped**; the dashboard has no quick-create actions (create-from-list-pages only, jobs via quote conversion). *Applied:* corrected the Overview claim, rewrote the "Quick Actions" section to state there are no quick-create actions and that `QuickActions.tsx` + its barrel export are unmounted dead code. *Changed: Overview, Quick Actions section.*

- **Data Refresh: auto-refresh / manual-refresh / pull-to-refresh were documented but unimplemented.** *Doc said:* "Auto-refresh: refresh every 60 seconds", "Manual refresh: pull-to-refresh on mobile, refresh button on desktop". *Reality:* the dashboard fetches once on mount (`useEffect` in `page.tsx`, `useLoad` in `PinnedMetrics`); there is no auto-refresh, refresh button, or pull-to-refresh. **Decision (canonical model):** a manual "Refresh" button + fresh-on-mount + a visible "last updated HH:MM" timestamp; NO live subscription and NO default auto-poll. Optional opt-in slow refresh (5–15 min) only for a hands-free wall display. Escalate to real-time (SSE) only for a genuinely time-critical board (machine status / alarms), never KPI tiles. *Applied:* rewrote the Data Refresh section to document current "fetch once on mount" behavior as shipped and label the canonical model **Planned (#550)**; removed the stale auto/pull-to-refresh from Future Enhancements. *Changed: Data Refresh section, Future Enhancements.*

- **AI Insights area is implemented on the dashboard but was undocumented.** The page renders an AI Insights area (`InsightsChat` ask-bar + `InsightsSection` saved charts, gated on the per-company `ai_insights` feature flag). **Decision:** it is documented in `ai-insights.md`; the dashboard doc should **point to** that spec rather than duplicate it, noting only that the dashboard hosts the area flag-gated. *Applied:* added a short "AI Insights" section that references [ai-insights.md](../../modules/ai-insights.md) and records the `ai_insights` flag gating; no duplication. *Changed: added AI Insights section.*

## Informational / aligned

- **Open Quotes still counts `quotes.status = 'active'`.** The `quotes` table retains a `status` column (`active | expired`); the Open-Quotes metric filter (`getCount('quotes', …, { status: ['active'] })`) matches the doc. No change.
- **Empty states exist, though shaped differently.** The doc's "Empty State: No recent activity." matches `RecentActivity` exactly; the `/activity` page uses "No activity yet."; whole-dashboard emptiness surfaces via `OnboardingCard` (`isEmpty` when all four core metrics are 0) rather than a bare message. Noted for completeness.
- **Drill-down navigation is intact.** Metric cards link to filtered lists (`?status=…` / `?overdue=true` on jobs, `?status=active` on quotes), and both list pages honour those query params (`useSearchParams`). Matches the doc's "Clicking summary cards navigates to filtered list".
- **Responsive layout matches intent.** `PinnedMetrics` renders `repeat(2, 1fr)` on `xs` and `repeat(4, 1fr)` on `md`, consistent with the doc's stacked-on-mobile / row-on-desktop description (updated for a 4-up grid rather than the doc's 3-up).
