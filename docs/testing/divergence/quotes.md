## Resolved (owner decision)

- **"Emailing a Quote" — email was INTENTIONALLY REMOVED.** The `QuoteEmailDialog.tsx` / `buildQuoteMailto(...)` path never merged to `main` (it lived only in an unmerged worktree), and email is descoped as a product decision. **Resolution:** the "Emailing a Quote" section and all `QuoteEmailDialog` / `buildQuoteMailto` / `mailto:` references were removed from the doc; a one-line "Email descoped" note now sits under Printing Quotes. The doc no longer presents Email as a shipped action.
- **Detail-page actions: standalone buttons (no overflow menu).** The shipped page renders four standalone controls — contained `Convert to Job`, outlined `Edit`, outlined `View PDF`, red `Delete` `IconButton` — gated purely by `converted_at` (an in-file comment documents this deliberate shop-floor/older-user choice). **Resolution:** the doc's UI Screens §3 actions block was rewritten to the standalone-buttons layout; the primary+overflow-menu description and the Email menu item were removed. The by-status table now reads: not-converted → Convert/Edit/View PDF/Delete; converted → View PDF/Delete (Convert + Edit hidden). Expired-price warning is noted as surfacing in the Convert modal, matching the code.
- **`payment_terms` is REQUIRED.** The code enforces it — `QuoteForm.tsx` blocks submit when `payment_terms.trim() === ''`, verified by `__tests__/components/quotes/QuoteForm.test.tsx > 'requires payment terms — submit stays disabled until they are set'`. **Resolution:** the three "optional" mentions (Data Model table line 92, Create/Edit form line 208, Validation Rules line 704) were corrected to "required"; the Data Model Required column for `payment_terms` flipped No → Yes. The doc is now internally consistent with the already-correct Detail-View header prose.
- **`quote_line_items.quantity` is FRACTIONAL (numeric), not integer.** The column is `numeric NOT NULL` with `CHECK (quantity > 0::numeric)` in `schema.prod.sql` (no integer check); fractional quantities are a supported, tested path — `__tests__/utils/quotesAccess.test.ts > 'createQuote (validation paths)' > 'forwards a fractional order_quantity unchanged (parts sold by length/weight)'`, `__tests__/components/quotes/QuoteForm.test.tsx > 'accepts a fractional order quantity (parts sold by length/weight) and forwards it'`, and `e2e/fractional-quote-to-job.spec.ts`. **Resolution:** the Data Model table (line 115) now types it `Numeric` and calls out fractional support; the "whole number > 0" wording in both Validation sections (create/edit guards + Validation Rules) was corrected to "number > 0 (fractional allowed)".
